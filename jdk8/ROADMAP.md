# 剩余工程与阶段验收

固定基线与当前完成标记沿用 PROGRESS.md 的 `jdk8-m9`。整体目标仍未完成。单个里程碑通过不代表整个项目结束；排除项只有用户指定的 Guardrails、Spring Boot Starter、Jackson 3。

## 全量范围

[模块清单](MODULE-INVENTORY.md) 枚举基线全部 POM，[机器可读清单](MODULE-INVENTORY.json) 保留每个模块的直接依赖声明与模型/向量库源码候选证据。其他分类尚须人工核对；清单不构成依赖 Java 8 审计，更不代表功能通过。新增 SQLite 属于本分支扩展，单独记录于现有支持矩阵。

## 执行顺序

1. MCP：stdio 与子进程生命周期；资源、模板、提示词、日志、进度、工具/资源/提示词缓存变更；HTTP 与 stdio 端到端及独立 BOM 消费。当前第十阶段 WIP，未宣布通过。
2. MCP：WebSocket、Registry、固定基线其他协议；逐能力验证会话、取消、超时、恢复和释放。自动恢复不重发原工具请求。
3. Agentic：四个候选模块完整公开能力及依赖审计，然后基础 Agent、顺序/条件/并行/循环、状态与记忆、错误与取消、生命周期，以及审计发现的其他基线能力。逐能力记录实现和验收，不能用最简单的顺序示例代替完整支持。
4. 模型与向量库：从完整清单逐模块推进；解析有效 POM 与传递依赖、确认 Java API/字节码，再实现并以本地模拟服务验收功能。只审计、只编译或声明不支持不计完成。新发现模块补入清单，不隐式排除。
5. 总体验收：所有纳入模块的 clean 构建、实际 Java 8、原有回归/TCK、独立 BOM 消费、字节码/API/链接审计；迁移说明、支持矩阵、已知限制、结果快照、Git 提交和最终标签齐全后，逐项核对整体目标。

## 每模块检查点

- [ ] 精确公开 API/功能范围与有效生产依赖清单。
- [ ] Java 8 实现，保留语义并记录必要差异。
- [ ] 本地功能、并发、错误、取消、超时和释放验收。
- [ ] reactor/BOM、独立消费与运行时审计纳入。
- [ ] 全部旧回归保持通过；阶段 clean 验收与结果快照。
- [ ] 进度/支持矩阵/迁移说明、提交与阶段标签。

确有无法解决的阻碍须记录具体失败和来源证据，并保持整体未完成；不能通过缩小范围或跳过失败测试达成结束条件。
